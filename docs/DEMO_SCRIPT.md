# 5 分钟演示脚本 — Stage 8

## 演示前准备

按 README 启动合成数据 API / 前端，导入制度索引。运行：

```powershell
./.venv/Scripts/python.exe scripts/run_evals.py --confirm
```

记下 stdout 的 report_path。先在工作台 Evaluation 选择对应 report.json，再回到“任务与分析”。报告刷新后需重新导入。
为演示批准 / 拒绝各准备一份合成工作流，分别使用唯一幂等键，保存申请 ID；所有创建、审批、执行均通过确认弹窗。
不得复用同一申请展示拒绝后又批准，拒绝是终态。建议先完整彩排。

## 0:00–0:35 业务与边界

展示工作台和合成数据提示：订单、库存、供应商与制度分别提供证据，人工决定业务写入。
当前离线 Mock adapter 整理事实，没有真实 LLM；MCP 是真实 stdio 协议，ERP 数据来自本地数据库。

## 0:35–1:35 任务、Timeline、工具和最终结论

默认问题：

> PO-2026-10086 为什么无法按期交付？给出补货建议，追加采购先让我审批。

点击“运行只读分析”。展示 Final Result、Agent Timeline 和工具参数。
核对需求 100、在手 30、占用 8、可用 22、缺口 78；交期 10 月 12 日晚于订单要求 10 月 10 日，共 2 天。
计算由确定性代码完成。展示 get_purchase_order / get_inventory / get_supplier 的 mcp:stdio 通道，retrieve_policy 为本地检索。
指出此按钮不保存草稿；独立分析结果仅在当前页面响应中保留。

## 1:35–2:05 制度证据

展示分析结果中的制度摘录、文件、章节和行号。也可切换“制度证据”查询“紧急采购超过 20000 元需要谁审批”。
报告中的引用检查会核对源快照、行号、摘录和哈希。检索是字符 n-gram TF-IDF，不宣称语义模型。

## 2:05–3:20 人工审批和 Final Result

切到“持久工作流”，展示准备好的 WAITING_APPROVAL 运行及申请 ID；必要时创建新运行，明确人工填写草稿参数和确认。
切到“人工审批”，按同一申请 ID 查看，批准后回到工作流点击“恢复运行”：仍为 WAITING_EXECUTION。
点击“确认执行并恢复”，人工确认后展示 COMPLETED 和持久 Mock 回执。
执行只保存本地回执，库存、订单均不改变。
另一份申请演示拒绝，回到工作流恢复后为 REJECTED，无回执。

## 3:20–4:10 恢复与幂等证据

展示已准备的等待审批运行，停止自己启动的 API，按 README 原命令使用同一数据库与索引重启。
刷新工作流列表并查看原 ID：分析 run_id、申请 ID 和 checkpoint 保持，恢复不重建已提交草稿。
解释保存前中断的只读分析可能重做；已提交业务阶段与 checkpoint 同事务。
现场时间不足时展示 Stage 7 restart_resume 的实际两个进程证据，明确说明这是预先运行的记录。
可重复命令：`$env:PYTHONPATH='backend'; ./.venv/Scripts/python.exe scripts/stage6_demo.py --confirm`。

## 4:10–5:00 Evaluation 与收尾

切到 Evaluation：展示导入报告的完成数量、每项分子 / 分母和任务明细，翻页查看 restart_resume / idempotent_creation。
基线报告 17/17，工具参数 8/8、引用 7/7、审批 5/5、恢复 1/1，观测到的未授权业务效果 0/17。
每次以实际导入报告为准，失败时展示失败检查，不隐藏失败或把不适用算成功。
说明 UI 导入不执行评测，也不独立验证报告真实性。成绩是固定 Mock 合成任务验收，不是 LLM 智能或生产安全认证。

## 常见故障

- 后端无法连接：服务状态只检查 API 存活；业务还需要数据库、迁移、seed 和制度索引。
- 请求超时：先刷新查询原运行；保留原幂等键和输入，不换键重建。硬崩溃租约最多等待 60 秒。
- 幂等键冲突：同键输入必须一致；新演示使用新键，重试使用原键。
- 无制度依据：保留“未找到依据”，不补造引用。
- 导入失败：选评测器生成的 report.json，不选逐任务证据文件；上限 2 MB。
