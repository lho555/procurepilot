# 百炼 qwen3.7-flash 验收

已核对的模型配置为百炼华北 2（北京）旧域名 `https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions`、模型 `qwen3.7-flash`。官方仍支持该域名，本切片沿用已选配置，不自动迁移业务空间地址。

## 显式关闭思考

选用 `PP_LLM_PROVIDER=bailian` 后，应用在 HTTP 请求 JSON 顶层固定发送：

```json
{
  "model": "qwen3.7-flash",
  "enable_thinking": false,
  "temperature": 0,
  "max_completion_tokens": 1024
}
```

HTTPX 直接请求不需要 `extra_body`。保留 JSON 输出与全部事实 / 引用 / 建议校验；百炼配置不发送其文档未列出的 `store` 字段，不能由此推断提供方的数据留存政策。原通用协议仍发送 `store=false`，其行为保持不变。

非秘密示例见 [bailian.env.example](../profiles/bailian.env.example)。它保持 `PP_LLM_MODE=offline` 与发送许可关闭，密钥为空。日常应用要在线运行仍需另行配置本机密钥、模型模式和合成数据发送许可；复制示例不会自动调用模型。专用百炼配置仅接受上述已核对的地址和模型。

协议依据：[百炼官方 Chat 参数](https://help.aliyun.com/zh/model-studio/qwen-api-via-openai-chat-completions)。`enable_thinking=false` 明确关闭思考，`max_completion_tokens` 限制完整输出；官方说明实际输出可能比设定多最多 10 个 Token，因此预算计入这部分余量。

## 安全失败分类（离线验证）

后续执行若因异常停止，报告与 CLI 摘要增加 `failure` 对象，只允许固定类别、固定阶段、合成案例编号和有界 HTTP 状态码。例如，以下为本地响应替身模拟的限流失败，不是真实服务结果：

```json
{
  "category": "provider_http",
  "phase": "model_request",
  "case_id": "shortage_only",
  "http_status": 429
}
```

| 类别 | 含义 |
| --- | --- |
| `credential` | 指定凭据加载阶段（含其前置复核）失败，不表示已读取密钥或密钥无效 |
| `configuration` | 适配器配置被拒绝 |
| `input_context` | 缺少或超限的事实 / 制度上下文 |
| `timeout` | 模型请求阶段超时 |
| `transport` | 模型请求阶段连接或传输失败 |
| `provider_http` | 收到非 200 HTTP 状态；只保留 100～599 的整数状态码 |
| `response_limit` | 响应超过本地字节限制 |
| `output_contract` | JSON、响应结构、完整结束、事实 / 引用 / 建议约束未通过 |
| `local_processing` | 请求准备、预留落盘、结果检查 / 落盘或未识别的程序异常 |

阶段为 `credential`、`configure_adapter`、`prepare_request`、`reserve_request`、`model_request`、`validate_result` 或 `persist_result`。程序按发生阶段区分失败，避免将本地写盘或评分异常误报为供应商失败；未知异常不按内容猜测根因。HTTP 状态仅在模型请求阶段、明确的服务状态失败中保留，布尔值、超范围值或文本均不输出。

不保存异常文字、异常类名、响应正文、认证头、供应商请求 ID、主机名或凭据路径。正常完成与非异常的质量 / usage 缺口均为 `failure=null`，仍须读取 `passed`、`status` 与逐项检查，不能把 null 当成整体通过。异常仍停止后续调用，不重试、不退款、不重置领取。

预检被拒绝或最终报告无法落盘时仍返回固定 CLI 错误，不能保证存在分类报告；已创建的领取记录仍不能删除重跑。旧报告没有 `failure` 字段，表示该分类未记录，不能解释为成功或事后补推根因。2026-10-19 真实第二次请求继续保持原因未知，既有证据不改写。
