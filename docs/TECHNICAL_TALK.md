# 15 分钟技术讲解 — Stage 8

## 0:00–2:00 业务切片与范围

问题：采购订单延迟时，需要关联订单、可用库存、供应商交期和采购制度，再交人工审批。
打开 ARCHITECTURE 的实际运行图。Python / FastAPI 单体模块化，MySQL 为主线，SQLite 支持隔离验收。
外部 ERP、LLM、支付均为未接入能力；真实的是 MCP 协议和本地业务流程。

## 2:00–4:00 数据与计算

打开 `backend/app/models.py`、业务查询和合成 seed。
可用库存 = 在手 − 占用；缺口 = max(需求 − 可用, 0)，日期差由代码计算。
展示异常订单缺口 78 / 延期 2 天与正常订单对照。
解释严格输入校验、404 / 409 / 503、迁移与种子数据不覆盖已有记录。

## 4:00–6:00 LangGraph 与 MCP

打开 `backend/app/agent.py` 和 `backend/app/mcp_tools.py`，对应页面 Timeline。
七个固定节点，facts / policy / trace / tool_calls 在 State 内流转。
客户端白名单只读，实际 stdio Server 调用 SQLAlchemy 业务查询；server 有草稿工具，Agent 不拥有它。
工具重试与超时有界，失败停止下游。Mock adapter 整理固定事实，当前没有模型自主工具选择。

## 6:00–8:00 RAG 与可解释证据

展示制度索引及引用。章节分块、字符 n-gram TF-IDF、余弦阈值，源快照和行号 / 哈希使摘录可核对。
优点是离线可重现；局限是词面匹配，对同义改写弱，制度变更需重新导入。
无命中返回无依据，不能补造政策；引用正确不等同于建议正确。

## 8:00–11:00 审批、事务与恢复

打开 `backend/app/workflow.py`、`backend/app/approval.py` 和迁移 0003。
创建明确输入与严格确认；草稿 / 提交审批和 checkpoint 同事务，回执 / 完成 checkpoint 同事务。
同键同输入返回已有结果，同键不同输入冲突；事务回滚防半提交，数据库唯一约束和租约 owner_token 处理竞争。
批准仍需单独执行确认，拒绝终止；本地动作唯一，库存不变。
展示实际重启证据，完整分析保存后不重做。保存前崩溃可能重做读取，硬崩溃等待最多 60 秒租约。
明确应用层业务 checkpoint 与 LangGraph 原生 checkpointer 的差异，无外部 exactly-once 或自动恢复 worker。

## 11:00–13:00 Evaluation 与失败模式

打开 `evals/golden_tasks.json`、scorer 和报告：17 条任务覆盖缺输入、错误 SKU、写入诱导、确认、审批拒绝和恢复。
工具名称与参数精确比对；引用检查文件 / 行号 / 摘录 / 哈希；业务效果核对申请、回执、库存与订单。
解释不同指标不同分母，适用运行失败留在分母，不适用不算成功。
UI 本地导入展示报告，不验证报告真实性。成绩不表示真实 LLM 推理能力。
指出错误工具参数、额外调用、伪造引用、失败分母都有评分器负向测试。

## 13:00–15:00 取舍与生产差距

当前单体 / JSON 索引足够演示，不引入无业务用途的中间件。
若继续生产化：先做身份鉴权和审批人隔离，再接只读真实数据与模型，建立现实任务 / 失败基线。
外部写入需服务端授权、幂等协议、回执对账和补偿设计；现有本地事务不能保证外部系统 exactly-once。
