# frontend

Stage 0～8 React + TypeScript + Vite + Ant Design 工作台：健康状态、订单关联查询、供应商报价查询、采购草稿确认、制度查询、来源快照和只读 MCP 工作流分析。执行记录展示 MCP / 本地通道。
人工审批卡片查询最近 100 份申请：草稿提交、批准 / 拒绝和本地 Mock Action 均需分别确认，拒绝后按钮禁用；批准不会自动执行。
页面刷新后可重新读取业务审批记录和回执；独立只读分析卡片的运行状态不持久化。

新增持久工作流：明确草稿参数和幂等键，确认创建 / 提交审批，刷新列表查看持久分析和 checkpoint。
批准 / 拒绝后恢复；批准的恢复不授权执行，另设确认执行入口。独立只读分析卡片仍不保存运行历史。

```powershell
cd frontend
npm ci
npm run dev
```

访问 http://127.0.0.1:5173。页面通过 `/api/health` 请求 Vite 代理；代理移除 `/api` 前缀，转发到根目录 `.env` 的 `BACKEND_URL`（默认 `http://127.0.0.1:8000`）。修改 `.env` 后重启 Vite。

`npm run build` 执行 TypeScript 检查及构建；`npm run preview` 在 4173 端口本地预览并使用相同代理。
静态生产部署需要另外配置 `/api` 反向代理；Vite preview 只用于本地预览。

业务数据库需先迁移和 seed。订单默认 `PO-2026-10086`，可替换为正常订单 `PO-2026-10087`。
页面按订单取库存和供应商，缺口通过确定性计算展示；它是单订单参考值，不代表库存预留。
取消草稿对话框不会发起 POST；只有点击“确认保存草稿”才发送带显式确认字段的请求。
保存时禁用重复点击，不自动重试写入。此页面没有生产身份验证或采购执行能力。

“采购制度查询”仅发送只读问题，通过引用显示章节、文件名和行号，来源对话框显示导入时保存的文档快照。
如果索引版本变化导致来源哈希不一致，要求重新查询；无依据或索引不可用时显示明确提示并清除旧回答。
需要先从根目录执行知识导入，命令见根目录 README。此页面使用词面检索和原文摘录，不是生成式 LLM 回答。

“订单协同分析”发送只读分析请求，展示最终状态、事实摘要、工具尝试记录与制度引用。
请求最多等待 30 秒，后端总等待默认 25 秒；开始新分析时清除旧结果。
当前使用 Mock adapter，无实时 SSE、持久运行历史或自主写动作。
